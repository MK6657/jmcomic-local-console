## 安全的第一轮检查

以下命令使用临时数据与本机连接，可与日常实例并存。完整解压候选ZIP，保留EXE旁的 `_internal` 目录，在该目录打开PowerShell：

```powershell
.\JMComic.exe self-check
.\JMComic.exe lifecycle-check
```

两条命令都必须退出码为0，最后一行JSON中 `status` 为 `ok`。第一条检查打包资源、设置API及本机模拟取图；第二条两次运行真实服务入口，检查设置保存、停机记录清理和重启恢复。它们不验证真实上游可用性。

## 界面与真实使用复检

普通服务仍共用Windows单实例锁。需正常使用界面时，先从原启动窗口关闭日常服务，再从独立候选目录启动；先用新实例数据检查，不把新包直接覆盖到个人目录。

建议依次观察：

1. 打开设置后立即修改并保存，切换页面、重启后核实；检查0值、关闭的开关及原有未修改字段。
2. 检查暂停、恢复、取消和失败任务重试；多个任务排队时，失败或中断任务不应永久阻止后面的任务。
3. 检查在线阅读加载、跳页和清缓存；有请求在途时发起正常退出，观察成功退出或明确的未排空提示。
4. 停机后重新启动，确认设置保留、主动暂停仍暂停，中断任务按队列规则恢复。
5. 仅在可丢弃实例中测试备份及恢复到新目录；数据库/清单备份不包含资源文件。个人数据维护说明见 [数据维护](DATA_MAINTENANCE.md)。

真实接口应按搜索、详情、在线阅读和下载分别记录；需要下载时使用用户指定的少量授权内容。启动健康、自检和离线回归通过，不等于这四类接口都已验证。

## 仍然保留的边界

- 不安全地终止Python线程或并发关闭正在请求的curl句柄，不属于停机策略。在途调用尚未返回时，排空可以超时；所有权和实例锁保持到实际结束，不会宣称已完成。
- 普通窗口关闭、系统强制结束与系统关机，需要单独验收；它们不等同于启动器的正常协作停机。
- 真实上游下载、干净Windows系统、签名/安装包及Linux/Docker另有验收范围；本次交接不代表这些项目已经完成。
- Windows与Docker的后续维护继续共用Python核心与上游SDK边界；本轮未引入Rust、UI框架或新运行依赖。
