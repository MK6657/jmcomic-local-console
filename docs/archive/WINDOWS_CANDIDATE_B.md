# Windows 候选包：路线 B 第一阶段

2026-11-18，分支 `codex/refactor-windows`。本次修复 Windows 日常使用与文件完整性问题；验收实例只包含合成图片和任务。上一轮审查的 Git 基线为 `43a2c457da72208ad58ca1856500e3f5aa758cdd`，本轮产品修复止于 `fb502664c48a6fa253a3267504957b3090f18f32`，随后一笔是随包说明与本交接文档。提交保存在本地分支；此候选未上传 GitHub。`main` 和日常实例没有参加测试。

## 拿到包后怎么试

1. 先完整解压到新的可写目录，保留 EXE 旁边的 `_internal`。不要把包直接覆盖在正在使用的版本上。如果以往配置过 `JMCONSOLE_HOME` 或其他 `JMCONSOLE_*_DIR`，确认不会指向日常数据。
2. 在解压目录的 PowerShell 运行 `./JMComic.exe self-check`、`./JMComic.exe lifecycle-check`。两者都使用自己的临时实例，末行应为 `status: ok`、退出码 0。普通双击运行有单实例限制；日常服务若在运行，应从原窗口正常退出后再单独试用。
3. 最容易人工验证的是设置：同时打开两个设置页，在 A 改超时并保存；不刷新 B，在 B 改重试次数并保存。从候选的启动窗口正常退出，重开同一候选实例，两项应同时保留。手工复检其他场景的具体预期见 [后端复检交接](BACKEND_REVIEW.md)。

## 本次修复及验收方法

| 现象 | 验收重点 |
| --- | --- |
| 下载根切换后，同名备份可能替换掉最后一份能恢复的 ZIP | 普通备份先在只读数据库快照上按恢复规则检查任务与独立资源记录，再发布清单或完整包。检查失败时旧包哈希不变，实际恢复仍成功。只用于诊断、迁移的数据库快照继续不扫图。 |
| 自动打包过程中退出，或清理原图时取消 | 在文件成员之间和最终替换前协作检查；取消后不开始下一次原图删除。在旧包被替换前停机，旧包哈希应不变；已经发布的新包应完整，尚未删除的散图应还在。已开始的单个文件操作不会被强行终止。 |
| 为同一本补章时，按作者整理会把旧章移出资源库记录的位置 | 有可读的成功记录时留在原目录；新书仍可按作者整理。补章中取消后，原成功资源仍能在阅读器打开。 |
| ZIP、PDF 以成功响应送出漏掉整章的附件 | 目录枚举或条目信息读取失败，两种格式都返回 `503/export_source_unreadable`，不发附件，归还导出名额；解除故障后实际解 ZIP、解析 PDF 核对两页。 |
| 另一个旧设置页把已保存的字段改回默认值 | 普通保存只提交本页相对基线的改动；保留 `0`、关闭的开关及保存过程中产生的新草稿。显式关闭自动打包会一起关闭删除原图。两页刻意修改同一项时，最后一次成功保存生效。 |
| 图片重试设为 0 仍二次请求坏页，后面的任务额外等待 | 用真实 SDK/libcurl 和本机 HTTP 服务观察每页 GET 数、任务终态和磁盘上的好页。零重试首次失败即记录，不补抓；只有等待任务由调度器自动启动才算通过。主动暂停仍占当前名额，属于另一个行为。 |
| 搜索选 20、50 或 100 条/页时跳过结果 | 以 SDK 定义的页长换算偏移，跨页共享一次搜索的总超时。分别遍历固定的 1–96，顺序应完全相同；没有总数时仍能翻页，读取下一原生页失败时不发布半页结果。 |

- **压缩包：** `tools/build_windows.py` 的 EXE 自检与两进程启停都通过。随后对实际 ZIP 运行 `tests/check_windows_release.py releases/windows-x64-1daeb927906e --check-launcher --check-restore`：SHA-256、CRC、中文空格路径、无系统 Python、忙锁启动拒绝、旧库完整备份与恢复、切换下载根时旧包哈希不变，均通过。上次候选 `5f04eae8af14` 单独保留。
- **真实浏览器与便携 EXE：** 从该 ZIP 解压，在临时 v2 实例运行便携 CLI 完整备份、恢复到新目录。首次服务启动将库升级为 v4；阅读接口返回一页，取图 HTTP 200、SHA-256 与原图相同。Chromium 两个标签均从 `30/2` 起步，A 保存后服务为 `47/2`，旧 B 保存后为 `47/0`。下载页恢复一条合成的已暂停任务后显示排队（设置为非下载时段），在界面确认取消。正常关闭，再以同一数据目录启动另一个 EXE 进程：浏览器显示 `47/0`，任务仍是 `canceled`，读图哈希仍一致。两个临时服务已退出。
- **下载队列：** `tests/check_download_queue.py` 的本机 HTTP 服务配合真实 SDK/libcurl，两个任务只调用一次 `manager.start()`。一页停滞、一页返回坏图时约 6.3 秒；`--two-stalls` 两页分别停滞时约 12.3 秒。两种模式的四页请求数都是 `1/1/1/1`；首本保住 1/3 页并记下两个页号，后一本完成 1/1，两张好图均解码成功，结束时没有执行器占位。正数 `r` 沿用原策略：每趟最多尝试 `min(r+1, 可选节点数)` 个节点，只有首趟失败页才有第二趟，每趟内共享超时。
- **搜索与文件回归：** 96 条合成结果分别用每页 20、50、100 条，在 5、2、1 页内翻完。跨页错误不发半页，超时后在途客户端在实际结束前不关闭。备份覆盖保护分别验证了旧任务和仅剩资源记录、清单和完整备份四种组合。打包中途停机保住旧包哈希，删第一张原图后取消保住余下原图；导出故障解除后用 ZIP 目录及 PDF 解析器核对均为两页。
