# Windows vNext：旧视图的磁盘成本与三项离线测量

2026-11-18，Windows 源码版，使用临时实例和合成数据。**暂不自动删除 `.jmcomic-views` 中的旧视图。** 下例五次增量发布后，旧视图保留了 7.81 MiB，约为当前书架大小的两倍。所有任务已指回书架，但数据库路径和现有标记仍不足以安全递归删除旧目录。三项性能测量均为观察值，不设通过阈值。

## 旧视图：测到了什么，为什么保留

每次为同一书新增一章（8 张互不相同的 384 × 384 WebP），共五次，关闭整理与打包。脚本直接执行 `Workspace.seal/project`、`finish_download` 和 `release_pages`；有待办时执行真实的 `album_maintenance.claim/run`。每代都检查 `jobs.output_path`、`resource_catalog.output_path` 回到同一书架，核实当前页数和旧视图数量。下载根、数据库都属于本次探针。

| 累计发布 | 当前页数 | 旧视图数 | 当前书架逻辑字节 | 旧视图合计逻辑字节 | 旧视图文件分配字节 |
|---:|---:|---:|---:|---:|---:|
| 1 | 8 | 0 | 813,242 | 0 | 0 |
| 2 | 16 | 1 | 1,626,423 | 813,242 | 819,304 |
| 3 | 24 | 2 | 2,439,494 | 2,439,665 | 2,457,840 |
| 4 | 32 | 3 | 3,252,653 | 4,879,159 | 4,915,608 |
| 5 | 40 | 4 | 4,065,384 | 8,131,812 | 8,192,608 |

最后一代，书架 46 个文件，分配 4,096,232 B；旧视图 94 个文件，分配 8,192,608 B；5 份不可变快照另有 50 个文件，分配 4,116,640 B。快照供按任务导出，**不计入旧视图成本**。分配量取 Windows `GetFileInformationByHandleEx(FileStandardInfo).AllocationSize`，样本中每个文件只有一个硬链接；包含普通文件及标记的默认数据流，不含目录索引、MFT 等元数据。每次保留的是上一次的整册：本例额外保存了 `8 + 16 + 24 + 32 = 80` 张历史页。重下同一批页、打包删原图、保留用户文件、连续发布后只整理一次，磁盘曲线都会不同。

* `.jm-view.json` 记录发布任务 ID（`job`）和合成代号（`generation`）。合成代号仅对参与合成的任务顺序号排序后取摘要，不包含文件路径或内容，不能证明整棵文件树的归属或完整性。任务快照只记录该任务各页的路径和摘要；整册可能合并多个任务，也可能带有旧书架的图片、归档或用户后来添加的文件。因此，不能凭视图标记或同名归档判定目录可删。
* 目录被移开后，`jobs` / catalog 不再指向它；未完成的 `_move.displaced` 却可能还靠它恢复。新发起的受管图片请求会核对 catalog，旧路径失效时返回 404；这不代表已通过校验的读、正在枚举和打开后续页的整册导出、或外部文件句柄都已结束。任务快照保护的是按任务导出。
* 先遍历再递归删除不是原子操作。遍历后可以多出一个用户文件；Windows 遇到后面的分享拒绝前，前面的文件可能已经删掉。仅凭年龄、无 DB 路径、能改名，或“已知图片的摘要都匹配”，都不能保证整棵树安全。保留现有未知文件、占用文件、未证实归属的历史归档和恢复现场，不扫描或回收活跃任务/私有快照。

若要上线自动回收，首先需要与每代发布/整理对应的**整树归属证据**（包含允许的目录、文件、布局、归档摘要），以及能与发布、恢复、读者和外部文件变更协调的隔离/复核机制。无法证明的旧代仍应保留。此次没有增加后台扫描、改写发布协议或启用手工清理命令。

## 三项实测

环境：Windows 11 专业版 x64，build 26300，AMD Ryzen 7 H 255（16 个逻辑处理器），可见内存 29.81 GiB；临时实例在本机 C: NTFS，分配单元 4 KiB。仓库 `.venv`：CPython 3.11.15、SQLite 3.53.1、Pillow 13.0.0、img2pdf 0.6.0、pikepdf 10.18.2、Flask 3.1.3、jmcomic 2.7.10、commonX 0.6.41、curl_cffi 0.17.0（libcurl 8.23.0-IMPERSONATE）。三轮串行，每项每轮都是新进程、新目录；图像由逐页固定随机种子生成，建库、生成输入不计时。未清空 OS 文件缓存；MiB = 1,048,576 B。

| 项目 | 输入 → 输出 | 三次耗时（秒，执行顺序） | 工作集：开始 → 采样最大值 | 临时空间 |
|---|---|---|---|---|
| 完整备份（M-15） | schema v5，数据库 180,224 B，6 章共 48 张 RGB PNG（512²、36.07 MiB）→ ZIP 36.09 MiB | 2.0438 / **1.9914** / 1.9322 | 37.80–37.98 → 40.69–40.88 MiB | 目标目录及系统临时目录合计约 **36.47 MiB**，含正在写的压缩包 |
| 仅有 CBZ 的整册 PDF（M-21） | 32 页、512²，CBZ 18.44 MiB → 32 页 PDF 6.02 MiB | 0.4678 / **0.4770** / 0.5175 | 50.70–50.89 → 55.17–55.79 MiB | 暂存预算计数峰值 **28.09 MiB**；临时目录含最终 PDF 的采样峰值 **31.10–31.32 MiB** |

**备份。** 在没有服务或活动任务的独立实例，调用 `create_backup(..., include_downloads=True, service_stopped=True)`，沿用默认 120 秒预算，包含发布前的解包校验。源资源 37,818,812 B；对源文件的 `_hash_file` 实测 144 次、113,456,436 B（两次 inventory 加一次写包）；另从 ZIP 回读、验哈希和 SQLite，核对生成的 50 个成员与 6,530 B 的 manifest。这里的 108.20 MiB 是应用读入源文件计算哈希的字节，不是物理磁盘 I/O；校验从 ZIP 解出的是数据库，不是再写出一份完整资源库。样本没有数 GiB 数据库或机械盘，不能推出固定容量必然超时。

**PDF。** 输入只有一个 ZIP_STORED 的 CBZ，包含 16 张带 alpha 的 RGBA PNG 和 16 张 JPEG，交替排列。通过 Flask 测试客户端调用 `POST /api/library/123/export/pdf`，不缓冲地接收整份响应并关闭，以 pikepdf 重新打开核实 32 页，核对服务端临时目录已清空。归档页内容合计 19,337,123 B；暂存预算的精确高水位是 29,451,686 B（解出原图、转码 JPEG 和单页 PDF）；6,315,583 B 的最终 PDF 属于独立的输出预算。表中磁盘采样包含服务端的最终文件，排除接收端副本。此样本不代表全 JPEG、全部需转码或回退重编码的册子，不能用一个倍数推算 413。

备份与 PDF 均用独立线程每次等待 5 ms，再枚举专属临时目录内可见普通文件的逻辑长度，并读取 Windows 进程工作集。备份每轮 275–287 次采样，PDF 每轮 41–44 次；列出的采样最大值不是文件系统或进程的精确峰值，未统计 OS 缓存、源文件和目录元数据。PDF 的预算计数直接观察 `resize_staging`，不依赖采样时机。

**SDK 回环（M-19）。** 同一个 `127.0.0.1` HTTP/1.1 keep-alive 服务，每轮每种模式 32 个请求、每次返回同一份 39,959 B JPEG，校验 HTTP 200 与全部响应字节。服务端在每次 GET 内加入 5 ms 等待，以便观察并发；直接在服务端计数 `accept` 和同时处理的请求。四组用同一个真实 SDK `get_image_once`/curl_cffi GET，改变客户端所有权或调用线程，均预热配置但不预发请求。

| 客户端与线程 | 每轮实际 TCP 连接 | 峰值同时处理请求 | 三次耗时（毫秒） |
|---|---:|---:|---|
| 下载式逐页 `get_client(shared=False)`，4 个工作线程 | 32 | 4 | 66.1 / 78.3 / 62.3 |
| 每线程独占并复用一个 `new_image_client()`，4 线程各 8 页 | 4 | 4 | 60.9 / 52.5 / 53.8 |
| 同一个共享元数据客户端，串行，但每个请求新建一个工作线程 | 32 | 1 | 235.2 / 261.4 / 234.2 |
| 同一个共享元数据客户端，同一线程串行 | 1 | 1 | 199.2 / 205.8 / 199.0 |

三轮连接数和并发数一致。减少新建连接的效果在本例中可复现；这只测传输和客户端生命周期，不跑上游元数据解析、下载解密、在线阅读池调度或重试。回环是明文 HTTP，没有 TLS 握手；未测 CDN、代理、HTTP/2、真实网络延迟或并发故障时的取消/关闭语义。没有因此更改线上池或超时。

## 复现

在项目根目录使用安装了项目运行依赖的 Windows Python（不要加 `-O`）。脚本只在新建的 `%TEMP%` 子目录初始化数据库，结束后自动移除；不启动应用服务。前三项用顺序执行避免探针互相争用，`views` 只需一次：

```powershell
$probePython = '.\.venv\Scripts\python.exe'
& $probePython tests/check_windows_vnext_measurements.py views
foreach ($trial in 1..3) {
    foreach ($probe in 'backup', 'pdf', 'sdk') {
        & $probePython tests/check_windows_vnext_measurements.py $probe
        if ($LASTEXITCODE -ne 0) { throw "$probe failed" }
    }
}
```

每项输出一行 JSON，保留原始字节、秒数和连接计数。脚本在 `tests/check_*.py`，不参与 pytest 自动收集；脚本和本记录均不在 `launcher.RESTART_GLOBS`、`tools/build_windows.py:SOURCE_PATTERNS` 或发行文档复制清单中。
